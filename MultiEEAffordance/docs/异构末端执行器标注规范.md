# Annotation Guideline for Heterogeneous End-Effector Multi-Label 3D Affordance Grounding

版本：v0.1  
记录日期：2026-05-11 +08:00  
适用范围：Multi-EE Affordance Dataset 的 VLM/SAM2 候选区域生成、人工标注审查、规则修正和后续质量控制。

## 1. 总体原则

### 1.1 标注对象

本项目标注的是 **任务相关的可操作接触区域**，不是物体上所有可接触表面。

给定一个 3D 物体点云 `P` 和任务指令 `q`，标注目标是输出四类末端执行器在该任务下分别应该优先接触、施力或形成机械约束的区域：

```text
P, q -> [M_gripper, M_suction, M_hook, M_dexterous_hand]
```

mask shape 固定为：

```text
[N, 4]

mask[:, 0] = gripper
mask[:, 1] = suction
mask[:, 2] = hook
mask[:, 3] = dexterous_hand
```

### 1.2 mask 的含义

某个执行器通道中的正样本点表示：

- 该区域与当前任务 `q` 直接相关；
- 该执行器可以通过其典型作用机制在该区域接触、施力或形成约束；
- 该区域在 object-level 几何意义上是合理的可操作区域；
- 该区域应优先作为执行器完成任务的候选接触区域。

某个区域只是“能被碰到”不等于应该标为 positive。只有当它能支持当前执行器完成当前任务时，才进入对应通道。

### 1.3 当前执行器抽象

当前阶段采用 **类别级 canonical end-effector prototype**，不绑定具体硬件型号。

也就是说：

- `gripper` 表示典型平行二指夹爪，而不是某一款具体夹爪；
- `suction` 表示典型单吸盘，而不是固定半径和材料的吸盘；
- `hook` 表示典型单钩或弯钩，而不是固定弧度的钩子；
- `dexterous_hand` 表示多指灵巧手，而不是某个具体型号的人形手。

当前不设定毫米级参数，例如：

- 不固定吸盘半径；
- 不固定 hook 弧度；
- 不固定夹爪开口宽度；
- 不固定灵巧手指长、关节数或材料。

但每类执行器必须满足抽象几何约束，例如相对接触、密封平面、可挂接结构、多指功能接触等。

### 1.4 当前标签边界

标签主要反映 **object-level geometry-based affordance**。当前不包含：

- 精确运动规划；
- 动力学仿真；
- 接触力优化；
- 材料摩擦建模；
- 真空动力学；
- 真实机器人控制误差；
- 遮挡下的抓取轨迹可达性精确判断。

如果一个区域在几何上明显不支持该执行器的作用机制，即使真实机器人通过复杂策略可能接触到，也不应在当前阶段标为 positive。

### 1.5 positive、negative、uncertain 的基本定义

| 标注状态 | 含义 | 处理方式 |
| --- | --- | --- |
| positive | 区域与任务相关，并满足该执行器的典型作用机制和必要几何条件 | 标入对应执行器通道 |
| negative / reject | 区域与任务无关，或不满足该执行器机制，或有明确几何 reject 条件 | 不标入对应通道 |
| uncertain | 信息不足、点云分辨率不够、视角看不清、结构是否可用无法稳定判断 | 不直接标 positive，进入人工复核或 refine 队列 |

## 2. 四类执行器定义

## 2.1 gripper：平行二指夹爪

### 2.1.1 执行器类别定义

`gripper` 指典型平行二指夹爪。它由两个相对的夹指通过闭合运动夹住物体局部结构。

### 2.1.2 核心作用机制

```text
opposing contact + clamping force
```

也就是：

- 至少存在一个适合夹指接触的表面；
- 该接触表面应能与另一侧或潜在另一侧表面形成相对接触；
- 夹持后能够产生稳定法向夹紧力；
- 接触区域在任务方向上能传递力或形成抓取约束。

### 2.1.3 mask 应该标注什么

gripper mask 应标注适合夹爪指面接触、并能与另一侧区域形成稳定夹持关系的表面区域。

标注时可只标出可见或可判断的一侧接触面，但必须满足“存在潜在成对相对接触面”的判断。不能把所有可接触表面都标成 gripper。

### 2.1.4 positive 标注标准

| 区域类型 | 是否可标 positive | 说明 |
| --- | --- | --- |
| 把手外侧 | 是 | 通常可被两指夹住，尤其适合 `open_pull` |
| 细长柄部 | 是 | 如刀柄、工具柄、杯把外侧，若厚度适合夹持 |
| 物体两侧相对面 | 是 | 如盒子两侧、瓶身两侧，需有稳定对夹可能 |
| 可夹持边缘 | 是 | 边缘必须有厚度或背侧支撑，不能只是无限薄轮廓 |
| 原始 grasp/hold 区域 | 候选 | 需要再检查是否满足二指夹持机制 |
| 按钮侧边 | 通常否 | 除非任务要求夹住按钮或开关结构，而不是按压 |

### 2.1.5 negative / reject 标准

| reject 情况 | 原因 |
| --- | --- |
| 大平面中心 | 无法形成相对夹持，只是可接触 |
| 光滑门板中心 | 更像 suction 或 palm push，不是二指夹持 |
| 孔洞内部深处 | 夹指无法稳定形成对夹，除非边界可夹 |
| 过小按钮 | 尺寸与稳定夹持不足，press_push 更偏 dexterous_hand |
| 细小不稳定结构 | 可能折断或无法承重 |
| 只适合吸盘的大平面 | 缺少 opposing contact |

### 2.1.6 uncertain 情况

- 点云看不清另一侧是否存在可对夹表面；
- 把手厚度、开口、背侧结构不清楚；
- 细杆或柄部是否足够粗、是否能承重不确定；
- VLM/SAM2 标出整片区域，但实际只有局部边缘可能可夹。

uncertain 不直接标 positive，应进入人工复核或 refine 队列。

### 2.1.7 常见错误标注

| 错误 | 为什么错 |
| --- | --- |
| 把整个物体表面都标为 gripper | gripper 需要成对或潜在成对的夹持面 |
| 把大平面中心标为 gripper | 不能形成 opposing contact |
| 把所有把手都标为 gripper | 有些把手可能太薄、太内凹或方向不适合夹爪 |
| `press_push` 中把整个按钮面标为 gripper | 按钮正面通常是 dexterous_hand 指尖按压区域 |

### 2.1.8 与其他执行器的区别

| 对比 | 区分标准 |
| --- | --- |
| gripper vs dexterous_hand | gripper 强调二指相对夹持；dexterous_hand 可以多指包覆、捏取、指尖按压或复杂手部操作 |
| gripper vs hook | gripper 夹住外侧表面；hook 需要进入、挂住或绕过结构 |
| gripper vs suction | gripper 需要相对接触面；suction 需要可密封低曲率表面 |

## 2.2 suction：单吸盘执行器

### 2.2.1 执行器类别定义

`suction` 指典型单吸盘执行器。它通过吸盘与物体表面形成局部密封，并沿表面法向产生吸附力。

### 2.2.2 核心作用机制

```text
surface sealing + normal adhesion
```

也就是：

- 吸盘 footprint 能覆盖局部表面；
- 局部表面应连续、低曲率、无明显孔洞或缝隙；
- 表面法向应可接近；
- 吸附后能沿任务方向传递足够约束。

当前 suction 标签主要基于几何可吸附性，不对材料孔隙率、真实密封性、真空动力学和控制误差作强判断。

### 2.2.3 mask 应该标注什么

suction mask 应标注吸盘 footprint 能够覆盖并形成稳定密封的低曲率、连续、法向可接近表面区域。

不能把所有平面都标成 suction。标注区域必须同时满足任务相关性和几何吸附性。

### 2.2.4 positive 标注标准

| 几何条件 | 标准 |
| --- | --- |
| 面积 | 局部区域应足够容纳 canonical suction footprint，不能只是很窄的条带 |
| 曲率 | 低曲率、近似平整或缓慢变化 |
| 连续性 | 表面连续，无明显孔洞、缝隙、镂空、断裂 |
| 法向可接近性 | 吸盘可以从表面法向方向接近，不是深凹或被遮挡结构 |
| 边缘距离 | 尽量远离尖锐边缘和薄边，避免 footprint 跨出表面 |
| 任务相关性 | 吸附后能完成拿起、搬运、拉开或推动任务 |

常见 positive：

- 盒子顶面；
- 柜门或抽屉面板；
- 可拉开的平整门板；
- 盘面中心；
- 宽阔平整的杯盘外表面；
- 对 `pick_up/lift_carry` 可承载的平整局部区域。

### 2.2.5 negative / reject 标准

| reject 情况 | 原因 |
| --- | --- |
| 孔洞、缝隙、镂空 | 无法形成稳定密封 |
| 边缘、薄边、尖角 | footprint 容易跨出表面或漏气 |
| 细杆、把手、拉环 | 接触面积不足或曲率过大 |
| 高曲率区域 | 难以形成密封 |
| 粗糙或 perforated 表面 | 当前几何标签中应保守 reject |
| 按钮、小开关 | 面积通常不足，且任务更偏 dexterous_hand |
| 只可接触但与任务无关的平面 | 缺少任务相关性 |

### 2.2.6 uncertain 情况

- 点云缺少法向，无法判断表面平整性；
- 区域局部看似平面，但面积是否足够不确定；
- 是否存在细小缝隙或孔洞不清楚；
- 面板可否被吸附后拉开不清楚；
- VLM 把整片大面板标出，但边缘和把手附近应被排除。

### 2.2.7 常见错误标注

| 错误 | 为什么错 |
| --- | --- |
| 把所有平面都标为 suction | 还需要面积、连续性、边缘距离、任务相关性 |
| 把把手标为 suction | 把手通常曲率高且面积不足 |
| 把孔洞边界标为 suction | suction 需要密封，孔洞边界通常漏气 |
| 把耳机连接处等小局部平面标为 suction | v0.1 采用保守 canonical suction，不标极小吸盘可行性 |

### 2.2.8 与其他执行器的区别

| 对比 | 区分标准 |
| --- | --- |
| suction vs gripper | suction 需要可密封表面；gripper 需要相对夹持面 |
| suction vs dexterous_hand | suction 关注单点法向吸附；dexterous_hand 关注多指功能操作 |
| suction vs hook | suction 不需要孔洞或挂接；hook 必须形成机械扣挂 |

## 2.3 hook：单钩或弯钩执行器

### 2.3.1 执行器类别定义

`hook` 指典型单钩或弯钩执行器。它通过插入、绕过或挂住物体结构，在拉动或提拉方向上形成机械约束。

### 2.3.2 核心作用机制

```text
insertion + mechanical interlocking + pulling force
```

hook 标注必须同时考虑三步：

1. **能不能进入**：钩子是否有空间插入、穿过、绕过或接近目标结构；
2. **能不能挂住**：结构是否能阻止钩子滑脱，形成机械 interlocking；
3. **能不能沿任务方向施力**：挂住后是否能沿 `open_pull`、`lift_carry` 或 `pick_up` 方向形成有效拉力或提拉约束。

### 2.3.3 mask 应该标注什么

hook mask 应标注钩子能够插入、挂住、绕过或扣住，并能沿任务方向施力的结构区域。

不能把所有边缘都标成 hook。普通边缘只有在存在可扣挂的背侧、内侧、孔洞或凸缘结构时，才可能标为 positive。

### 2.3.4 positive 标注标准

| 区域类型 | 是否可标 positive | 说明 |
| --- | --- | --- |
| 把手内侧 | 是 | 尤其适合 `open_pull` |
| 孔洞边界 | 是 | 钩子可穿入并挂住边界 |
| 拉环 | 是 | 典型 hookable 结构 |
| 提手开口 | 是 | 如 bag handle |
| 剪刀环 | 是 | 可穿入或挂住 |
| pan handle hole | 是 | 典型孔洞挂接 |
| 凸缘背侧 | 候选 | 需要确认能绕过并防滑脱 |
| 普通外轮廓边缘 | 通常否 | 除非有可扣挂背侧或凹陷结构 |

### 2.3.5 negative / reject 标准

| reject 情况 | 原因 |
| --- | --- |
| 普通平面 | 无法插入或挂住 |
| 无孔洞的光滑表面 | 无 mechanical interlocking |
| 单纯外边缘 | 没有背侧约束，容易滑脱 |
| 按钮 | 通常不能挂接 |
| 只适合 suction 的面板 | 无可挂结构 |
| 太浅的凹槽 | 可能进入但不能稳定挂住 |

### 2.3.6 uncertain 情况

- 点云看不清把手是否有内孔；
- 拉环是否闭合不确定；
- 凸缘背侧是否足够深不确定；
- 孔洞尺寸是否能容纳 canonical hook 不确定；
- 任务方向是否能形成有效拉力不清楚。

uncertain 不直接标 positive，应进入人工复核或 PartNet-Mobility 部件补充。

### 2.3.7 常见错误标注

| 错误 | 为什么错 |
| --- | --- |
| 把所有边缘都标为 hook | hook 需要进入和挂住，不是接触边缘即可 |
| 把所有把手都标为 hook | 只有有内孔、开口或可绕过结构时才可 hook |
| 把门板平面标为 hook | 缺少机械扣挂 |
| 把按钮标为 hook | 按钮适合 press_push，不适合挂接 |

### 2.3.8 与其他执行器的区别

| 对比 | 区分标准 |
| --- | --- |
| hook vs gripper | hook 挂住内侧/孔洞/背侧；gripper 夹住外侧相对表面 |
| hook vs dexterous_hand | dexterous_hand 可用手指勾拉或捏取，但 hook 需要单钩机械 interlocking |
| hook vs 普通边缘 | 普通边缘没有可扣挂背侧或内孔时不算 hook |

## 2.4 dexterous_hand：多指灵巧手

### 2.4.1 执行器类别定义

`dexterous_hand` 指多指灵巧手。它可以通过多个手指和掌部形成复杂接触，实现包络握持、捏取、指尖按压、勾拉、旋转或精细操作。

### 2.4.2 核心作用机制

```text
multi-finger contact + functional manipulation
```

也就是：

- 多个接触点或接触面共同作用；
- 接触区域与任务功能相关；
- 手部可以形成稳定抓握、包覆、按压、拨动、旋转或精细操作；
- 不是所有 human-contactable surface 都是 dexterous_hand positive。

### 2.4.3 mask 应该标注什么

dexterous_hand mask 应标注灵巧手为了完成任务而进行多指接触、包络握持、捏取、勾拉、按压或精细操作的功能区域。

它不是“人手能碰到的表面”，而是“人手式多指操作为了完成当前任务应优先接触的区域”。

### 2.4.4 positive 标注标准

| 区域类型 | 是否可标 positive | 说明 |
| --- | --- | --- |
| 杯身、瓶身 | 是 | `pick_up/lift_carry` 中可包覆握持 |
| 把手 | 是 | 可握持、拉动、捏取或勾拉 |
| 柄部 | 是 | 如刀柄、工具柄 |
| 旋钮 | 是 | 可多指捏住并旋转 |
| 按钮、开关、按键 | 是 | `press_push` 中指尖按压或拨动 |
| 拉环 | 是 | 可用手指勾拉 |
| 普通大平面 | 通常否 | 除非任务是明确推压该平面 |
| 只适合 suction 的平面 | 通常否 | 缺少手部功能操作意义 |

### 2.4.5 negative / reject 标准

| reject 情况 | 原因 |
| --- | --- |
| 与任务无关的普通表面 | 只是可触碰，不是操作区域 |
| 光滑大平面 | 通常无法稳定抓握，除非是 `press_push` 的面板 |
| 过小不可操作点 | 不支持稳定多指或指尖操作 |
| 只适合吸盘的宽平面 | 缺少手部功能接触意义 |
| 深孔内部 | 手指不可达或非主要接触区域 |

### 2.4.6 uncertain 情况

- 物体类别不清，无法判断手部如何操作；
- 区域看似可抓，但是否能稳定包覆不确定；
- 按钮/开关是否为真实功能部件不确定；
- VLM 把整片物体外表面标为 dexterous_hand，需要人工收缩。

### 2.4.7 常见错误标注

| 错误 | 为什么错 |
| --- | --- |
| 把所有可接触表面都标为 dexterous_hand | dexterous_hand 是任务相关功能操作区域 |
| 把整个门板标为 dexterous_hand open_pull | open_pull 更应标把手、拉环或可拉边界 |
| 把只适合 suction 的大平面标为 dexterous_hand | 缺少稳定抓握或精细操作意义 |
| `press_push` 中漏标按钮/按键 | 按钮和开关是 dexterous_hand 的典型正例 |

### 2.4.8 与其他执行器的区别

| 对比 | 区分标准 |
| --- | --- |
| dexterous_hand vs gripper | dexterous_hand 可多指包覆、指尖按压和复杂操作；gripper 主要是二指对夹 |
| dexterous_hand vs suction | dexterous_hand 依赖手部功能接触；suction 依赖表面密封 |
| dexterous_hand vs hook | dexterous_hand 可用手指勾拉，但不要求单钩插入和机械扣挂 |

## 3. 四类任务下的标注规则

### 3.0 汇报用总览表：四类任务 × 四类末端执行器

这张表用于导师汇报或组会快速说明当前标注边界。表中的内容是标注优先级总结，不替代后续每个任务小节中的详细 positive / negative / uncertain 规则。

| 任务 | 任务目标 | gripper：平行二指夹爪 | suction：单吸盘 | hook：单钩/弯钩 | dexterous_hand：多指灵巧手 |
| --- | --- | --- | --- | --- | --- |
| `pick_up` 抓取拿起 | 使物体离开支撑面 | 标把手外侧、细长柄部、物体两侧、可对夹边缘；核心是能形成相对夹持 | 标平整、连续、低曲率且可承载吸附的局部表面，如盒子顶面、盘面中心 | 标提手、拉环、孔洞、可挂接结构；不能把普通边缘都标为 hook | 标杯身、瓶身、柄部、把手等可包覆抓握区域；不能泛化到所有可接触表面 |
| `lift_carry` 提起搬运 | 稳定提拉并持续搬运 | 比 `pick_up` 更保守，只标稳定承重的对夹面、粗柄、可靠把手 | 只标面积更充分、法向稳定、远离边缘且可承重的吸附区域 | 标可承重提手、闭合拉环、bag handle、孔洞边界 | 标可持续承重的包覆握持区域，如杯身、瓶身、承重把手 |
| `open_pull` 拉开/打开 | 对可动部件施加拉力 | 标可夹住并拉动的把手外侧、抽屉拉柄、拉手 | 只在平整门板/抽屉面板可吸附且能被拉开时成立 | 标把手内孔、拉环、可挂接拉手、孔洞边界，是该任务的强相关通道 | 标把手、拉环、可捏取/勾拉/握持的拉动结构 |
| `press_push` 按压/推动 | 对按钮、开关或面板施加推力 | 仅在夹爪前端可作为推压接触时标局部区域；不是默认抓取通道 | 通常不是主通道，仅在明确法向推压大面板时作为候选 | 通常弱相关或为空，不应强行标按钮或普通平面 | 标按钮、开关、按键、指尖按压区和可推动面板，是该任务的主通道 |

汇报时可用一句话概括：本数据集不是标注“哪里能碰”，而是按任务和执行器机制标注“哪里适合该执行器完成这个动作”。因此四个通道可以重叠，但必须分别满足对夹、吸附密封、挂接约束或多指功能操作机制。

## 3.1 pick_up：抓取拿起

任务目标：使物体离开支撑面并被拿起。标注重点是能够形成稳定初始抓取、吸附、挂接或手部握持的区域。

| 执行器 | positive 标注重点 | negative / reject |
| --- | --- | --- |
| gripper | 物体两侧、把手外侧、细长柄部、可对夹边缘 | 大平面中心、不可对夹表面、过小不稳定结构 |
| suction | 盒子顶面、盘面中心、平整连续且可承载吸附的区域 | 把手、边缘、孔洞、高曲率小区域、面积不足局部面 |
| hook | 提手、拉环、孔洞、可挂接结构 | 普通平面、普通边缘、无孔洞表面 |
| dexterous_hand | 杯身、瓶身、柄部、把手、可包覆抓握区域 | 无任务意义的大平面、只可触碰但不可稳定握持区域 |

注意：

- `pick_up` 可以相对 `lift_carry` 稍宽，但仍需要稳定拿起的几何条件。
- 大件家具或明显不可拿起物体应在 object-task 层面 reject，而不是强行标局部正样本。

## 3.2 lift_carry：提起搬运

任务目标：不仅拿起，还要稳定提拉和搬运。相比 `pick_up`，标注应更保守。

| 执行器 | positive 标注重点 | negative / reject |
| --- | --- | --- |
| gripper | 更稳定的对夹面、承重把手、较粗柄部 | 细小脆弱结构、浅边缘、可能滑脱的平面 |
| suction | 面积更充分、法向更稳定、可承重的平整区域 | 小局部平面、边缘附近、曲率较大区域 |
| hook | 可承重提手、闭合拉环、bag handle、孔洞边界 | 不能承重的装饰孔、浅凹槽、普通边缘 |
| dexterous_hand | 可包覆并持续承重的杯身、瓶身、柄部、把手 | 只能短暂接触但无法稳定搬运的区域 |

注意：

- `lift_carry` 的 positive 区域通常应是 `pick_up` positive 的子集或更保守版本。
- 若区域只能完成短暂接触，不能支持搬运，应标 negative 或 uncertain。

## 3.3 open_pull：拉开/打开

任务目标：对可动部件施加拉力，使其打开或拉出。该任务与把手、拉环、可拉部件强相关。

| 执行器 | positive 标注重点 | negative / reject |
| --- | --- | --- |
| gripper | 把手外侧、可夹住的拉手、抽屉拉柄 | 门板大平面、无法对夹的面板中心 |
| suction | 可吸附并能被拉开的平整门板、抽屉面板、柜门面板 | 把手、边缘、孔洞、不可移动平面 |
| hook | 把手内孔、拉环、可挂接拉手、孔洞边界 | 普通门板平面、无孔把手外侧、普通边缘 |
| dexterous_hand | 把手、拉环、可捏取/勾拉/握持的拉动结构 | 无明确操作意义的平面，除非任务是手掌推拉面板 |

注意：

- hook、gripper、dexterous_hand 往往与 handle / ring / pull part 强相关。
- suction 只有在平面部件可吸附且可被拉开时才成立。
- 如果物体不是 articulated object，或者没有可打开/拉动部件，应在样本级 reject 或标 uncertain。

## 3.4 press_push：按压/推动

任务目标：对按钮、开关、按键或可推动面板施加推力。该任务不等同于抓取。

| 执行器 | positive 标注重点 | negative / reject |
| --- | --- | --- |
| gripper | 仅在夹爪前端可作为推压接触时，标可推压边缘或局部面 | 普通抓取把手、与推压无关的侧面 |
| suction | 一般不是主通道；仅在明确作为法向推压大面板时可作为候选 | 按钮、小开关、边缘、把手、高曲率区域 |
| hook | 通常弱相关或为空；极少数可用钩背推压的结构可 uncertain | 按钮、普通平面、无拉挂任务的结构 |
| dexterous_hand | 按钮、开关、键盘按键、指尖按压区、可推动面板 | 与按压无关的普通表面、不可操作装饰区域 |

注意：

- `press_push` 中 dexterous_hand 与按钮、开关、指尖按压区域强相关。
- gripper 不是默认抓取通道，只有夹爪前端或夹指外侧能合理推压时才考虑。
- hook 通常为空或 uncertain，不应强行标注。
- suction 一般不是主通道，除非任务定义允许吸盘作为法向推压接触。

## 4. 跨通道关系

### 4.1 基本原则

四个 mask 可以重叠，但不能无差别重叠。

同一区域可以对多个执行器可用，但必须分别满足各自机制。例如：

- 一个杯把外侧可能同时适合 gripper 和 dexterous_hand；
- 一个带孔把手的内侧可能适合 hook，也可能适合 dexterous_hand 勾拉；
- 一个平整抽屉面板可能适合 suction open_pull，但不一定适合 gripper；
- 一个按钮可能适合 dexterous_hand press_push，但通常不适合 suction 或 hook。

如果一个区域只是“能接触”，但不满足某执行器完成任务的作用机制，则不能标为该执行器正例。

### 4.2 常见混淆与区分标准

| 混淆组 | 容易错在哪里 | 区分标准 |
| --- | --- | --- |
| gripper vs dexterous_hand | 把所有手能抓的区域都标为 gripper | gripper 需要二指相对夹持；dexterous_hand 可以多指包覆、指尖按压或复杂操作 |
| hook vs gripper | 把可夹把手也标为 hook | hook 必须能进入、挂住、形成机械扣挂；gripper 只需外侧对夹 |
| suction vs dexterous_hand | 把平整大面同时标给 suction 和 dexterous_hand | suction 看密封吸附；dexterous_hand 看任务相关手部操作。普通平面不自动属于 dexterous_hand |
| hook vs 普通边缘 | 把所有边缘标为 hook | hook 需要可扣挂背侧、孔洞、内侧边界或凸缘，不是接触边缘即可 |
| suction vs gripper | 把盒子顶面也标为 gripper | gripper 要相对夹持面；顶面更可能是 suction |
| hook vs dexterous_hand | 把手指可勾的区域都标为 hook | dexterous_hand 可以复杂手指操作；hook 是单钩插入和机械 interlocking |

### 4.3 重叠标注要求

允许重叠的前提：

1. 每个通道都独立满足自己的机制；
2. 重叠区域与当前任务直接相关；
3. 不是因为“看起来都能碰到”而无差别复制 mask；
4. 若只能确定其中一个执行器可行，其他执行器应标 negative 或 uncertain。

## 5. 人工审查 decision tree

对每个候选区域和每个执行器通道，按以下顺序判断。

### 5.1 决策流程

```text
Step 1: 该区域是否与任务 q 相关？
  否 -> reject
  是 -> Step 2

Step 2: 该执行器是否能以其典型作用机制作用在该区域？
  否 -> reject
  是/可能 -> Step 3

Step 3: 该区域是否满足必要几何条件？
  否 -> reject
  是 -> Step 4
  信息不足 -> uncertain

Step 4: 接触后是否能沿任务方向施力或形成稳定约束？
  否 -> reject
  是 -> Step 5
  信息不足 -> uncertain

Step 5: 是否存在明显 reject 条件？
  是 -> reject
  否 -> Step 6

Step 6: 是否仍有关键信息不足？
  是 -> uncertain
  否 -> positive
```

### 5.2 按执行器的必要几何条件

| 执行器 | 必要几何条件 |
| --- | --- |
| gripper | 存在相对或潜在相对接触面；局部厚度和形状可被夹指接触；夹持后不明显滑脱 |
| suction | 局部面积足够；低曲率；连续无孔洞；远离边缘；法向可接近 |
| hook | 可进入；可挂住；可防滑脱；能沿任务方向形成拉力或提拉约束 |
| dexterous_hand | 支持多指功能接触；可包覆、捏取、勾拉、按压或精细操作；与任务语义直接相关 |

### 5.3 明显 reject 条件

| 情况 | 处理 |
| --- | --- |
| 区域与任务无关 | reject |
| 只是可接触但不能完成任务 | reject |
| VLM/SAM2 标出背景、空白、噪声 | reject |
| 标到物体错误部位 | reject 或 refine |
| 几何机制不满足该执行器 | reject |
| 信息不足但可能可行 | uncertain |

## 6. VLM/SAM2 辅助标注规范

### 6.1 基本定位

Qwen3-VL + SAM2 的输出只能作为 **candidate mask proposal**。

它主要用于：

- missing-label mining：发现弱规则漏掉的候选区域；
- candidate region discovery：为人工审查提供候选；
- annotation acceleration：减少人工从零找区域的工作量；
- 对 refine/add_missing 队列进行小规模试验。

不允许直接把 VLM/SAM2 mask 当作 ground truth。

每个候选 mask 必须经过：

1. 任务相关性检查；
2. 执行器机制检查；
3. 几何条件检查；
4. reject 条件检查；
5. 人工确认或人工修正。

### 6.2 VLM/SAM2 常见错误

| 错误类型 | 说明 | 处理 |
| --- | --- | --- |
| 语义过度泛化 | 看到把手就标 hook，看到平面就标 suction | 按执行器机制重审 |
| 区域过大 | 标出整片门板、整只物体或背景 | 收缩或 reject |
| 区域错位 | 2D mask 投影后落到错误点云区域 | reject 或重新生成 |
| 漏掉细结构 | 孔洞、拉环、按钮在点云渲染中不清楚 | uncertain 或人工补充 |
| 物理机制错误 | VLM 认为语义相关，但几何上不可行 | reject |

### 6.3 mask provenance 字段

建议在 metadata 或通道级记录中加入 `mask_provenance` 或 `label_source` 字段，按执行器分别记录来源。

示例：

```json
{
  "mask_provenance": {
    "gripper": "original_affordancenet",
    "suction": "rule_refined",
    "hook": "vlm_sam_candidate",
    "dexterous_hand": "human_verified"
  }
}
```

### 6.4 provenance 含义

| provenance | 含义 | 是否可作为最终标签 |
| --- | --- | --- |
| `original_affordancenet` | 来自 3D AffordanceNet 原始 affordance mask 的直接或近似映射 | 只能作为 weak，需要审查 |
| `vlm_sam_candidate` | Qwen3-VL/SAM2 生成的候选 mask proposal | 不能直接作为 ground truth |
| `rule_refined` | 经过几何规则、部件规则或人工规则修正后的 mask | 可作为 weak 或 checked，取决于审查 |
| `human_verified` | 人工确认符合任务、执行器机制和几何条件 | 可作为 checked/verified |
| `rejected` | 候选区域被判定不符合标注标准 | 不进入正样本 |
| `uncertain` | 信息不足或争议较大，暂不判 positive | 进入复核或后续补数据 |

### 6.5 VLM/SAM2 候选进入数据集的条件

| 条件 | 要求 |
| --- | --- |
| 候选 mask 已生成 | 只是第一步，不代表可用 |
| 与任务相关 | 必须通过 |
| 执行器机制匹配 | 必须通过 |
| 几何条件满足 | 必须通过或经过人工确认 |
| 无明显 reject 条件 | 必须通过 |
| 人工审查 | 必须完成 |
| provenance 更新 | 必须记录来源和状态 |

## 7. 标注审查表建议字段

| 字段 | 含义 | 示例 |
| --- | --- | --- |
| `sample_id` | object-task 样本编号 | `xxx_open_pull` |
| `executor` | 当前审查执行器 | `hook` |
| `candidate_source` | 候选来源 | `vlm_sam_candidate` |
| `decision` | 审查结论 | `positive / reject / uncertain / refine` |
| `issue_type` | 问题类型 | `over_label / missing_positive / wrong_region / executor_mismatch` |
| `positive_region_note` | 正样本区域说明 | `handle inner hole` |
| `negative_reason` | reject 原因 | `plain surface, no interlocking` |
| `geometry_check` | 几何条件是否满足 | `pass / fail / uncertain` |
| `task_relevance_check` | 任务相关性 | `pass / fail / uncertain` |
| `quality_after_review` | 审查后质量 | `weak / checked / verified` |
| `review_notes` | 人工备注 | 中文说明 |

## 8. 质量等级建议

| quality flag | 使用条件 |
| --- | --- |
| `weak` | 规则或 VLM/SAM2 候选生成，尚未充分人工确认 |
| `checked` | 人工看过，明显错误已排除，可用于当前阶段分析或训练候选 |
| `verified` | 人工严格确认，边界清楚，适合作为评估或高可信样本 |

VLM/SAM2 输出默认不得超过 `weak`。只有经过人工确认后，才可提升为 `checked` 或 `verified`。

## 9. 快速审查 checklist

人工审查某个候选 mask 时，至少检查：

- 是否标到了物体而非背景；
- 是否与当前任务 `q` 相关；
- 是否符合当前执行器机制；
- 是否满足必要几何条件；
- 是否能沿任务方向施力或形成约束；
- 是否与其他执行器通道无差别重叠；
- 是否存在明显过标、漏标、错区；
- 是否需要标为 `uncertain` 而不是 positive；
- 是否记录了 provenance；
- 是否更新了 quality flag。

## 10. 一句话原则

**只标注“该执行器为了完成该任务应该优先使用的功能接触区域”，不要标注所有能碰到、看起来相关、或由 VLM/SAM2 自动给出的区域。**
