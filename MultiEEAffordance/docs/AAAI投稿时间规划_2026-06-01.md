## 3. 投稿目标必须讲清楚

论文不要写成“做了一个网页工具并标了一批数据”。投稿主线应明确为：

> 面向异构末端执行器的任务条件化 3D affordance grounding：给定物体点云和一个独立任务，预测四种末端执行器各自适合接触和施力的点级区域，并显式判断不可执行组合。

输入：

```text
物体点云 P + 独立任务 q
```

任务集合：

```text
lift
open
pull
press
push
```

输出：

```text
[M_gripper, M_suction, M_hook, M_dexterous_hand]
```

同时输出：

```text
[F_gripper, F_suction, F_hook, F_dexterous_hand]
```

其中：

- `M` 是长度为 `N` 的点级 mask。
- `F` 是执行器对当前物体和任务是否可行的 feasibility 分数。
- 五个任务在训练侧是五个独立类别。
- 旧复合任务只用于历史候选复用，不进入训练定义，不进入论文方法定义。

## 4. 论文至少要形成三类贡献

投稿 AAAI 不能只靠数据集规模。建议将贡献组织为三部分。

### 4.1 数据贡献

构建一个面向异构末端执行器的五任务点级 affordance 数据集：

```text
任务：5 类
执行器：4 类
标注：点级 [N,4] mask
额外标签：empty mask / feasibility
数据来源：3D AffordanceNet + PartNet-Mobility
```

必须突出：

- 同一物体、同一任务下，不同执行器的正例区域不同。
- 同一物体、不同任务下，正例区域不同。
- 某些 `object-task-executor` 组合没有可行区域，空 mask 是有意义的监督，而不是缺失数据。

### 4.2 方法贡献

提出一个任务条件化、执行器感知的点云 affordance 模型。

初版训练闭环使用：

```text
TaskExecutorPointNet
```

正式投稿模型建议逐步升级为：

```text
PointNeXt / Point Transformer backbone
+ independent task embedding
+ executor mechanism token
+ task-executor cross attention
+ feasibility branch
+ local geometry features
+ executor relation loss
```

### 4.3 评估贡献

除普通分割指标外，增加：

```text
per-task mIoU
per-executor mIoU
macro mIoU
macro Dice
feasibility F1 / AUROC
empty-mask accuracy
small-part recall
cross-source mIoU
executor overlap matrix error
```

这样论文才能回答：

```text
模型是否真的学到了不同执行器的物理差异？
模型是否能识别没有可行区域的情况？
模型是否能处理 button / knob / handle / loop 等小部件？
模型能否从 3D AffordanceNet 泛化到 PartNet-Mobility？
```

- 完成本人分配的人工审查批次。

- 记录典型错误和任务边界问题。
- 抽样复查 `reviewer_b` 的校准样本。

负责：

- 完成分配的人工审查批次。

## 18. 风险控制与降级策略

### 18.1 如果人工标注延期

优先保留：

```text
高质量 3D AffordanceNet 主集
PartNet-Mobility 的关键补充类别
empty-mask 样本
small-part 样本
严格 object-disjoint test
```

可以降级：

- PartNet-Mobility 全类别覆盖。
- 较低价值类别的全量标注。
- 非核心样本的二次复查。

不要降级：

- 五任务独立定义。
- 四执行器通道顺序。
- 空 mask 保留。
- test split 质量。
- 冲突样本处理。

### 18.2 如果模型效果一般

按顺序排查：

1. 数据 split 是否泄漏。
2. 标签是否有明显过大 mask。
3. 空 mask 是否过多或失衡。
4. 通道监督是否完整。
5. 小部件是否被下采样吞掉。
6. feasibility loss 是否生效。
7. backbone 是否过弱。
8. executor token 是否真的产生差异。

不要第一时间堆叠复杂模块。

### 18.3 如果 GPU 不够

优先保证：

- 一套强 baseline。
- 一套正式方法。
- 核心消融。
- 三个随机种子只用于最终关键配置。

可以减少：

- 非关键 baseline 的随机种子。
- 大量结构搜索。
- 过多 backbone 对比。

### 18.4 如果时间严重不足

最小可投稿版本：

```text
五任务人工审查数据集
PointNeXt baseline
Executor Token + Cross Attention
Feasibility Branch
主表
按任务表
按执行器表
empty-mask 结果
small-part 结果
一组跨来源结果
两张可视化图
核心消融
```
