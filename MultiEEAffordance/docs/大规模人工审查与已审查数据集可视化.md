# 大规模人工审查与已审查数据集可视化

## 当前任务策略

暂时只保留三类任务：

- `pick_up`
- `open_pull`
- `press_push`

`lift_carry` 与 `pick_up` 在当前点云数据和执行器定义下过于接近，后续第一版大规模人工审查默认排除 `lift_carry`。原始数据不删除，只在生成审查队列、v3 pipeline 和 reviewed dataset release 时过滤。

## 1. 生成大规模审查队列

从 `samples_checked_v0_1.jsonl` 展开成 channel-level 队列，每行是一个 `sample_id + task + executor` 审查单元：

```bash
python MultiEEAffordance/tools/build_large_scale_review_queue.py \
  --dataset-root MultiEEAffordance \
  --output-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --summary-json processed/metadata/v3_large_scale_review_queue_summary_v0_1.json \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --executor-scope feasible \
  --quality-scope needs_review \
  --limit 200 \
  --overwrite
```

如果要生成全量队列，去掉 `--limit`。

## 2. 跑 v3 候选生成 pipeline

用上一步生成的队列作为 `--pilot-csv`：

```bash
CUDA_VISIBLE_DEVICES=1,2 python MultiEEAffordance/tools/run_v3_pipeline.py \
  --dataset-root MultiEEAffordance \
  --config configs/qwen3vl_sam2_pilot.yaml \
  --pilot-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --stages views,plan,ground,project,grow,render,build \
  --allow-empty \
  --overwrite
```

该命令会生成 `processed/metadata/v3_candidate_samples_v0_1.jsonl`，用于进入网页人工审查。

## 3. 启动点级人工审查系统

建议 v3 审查时显式指定 v3 输出路径，避免继续写入 v2 默认文件：

```bash
python MultiEEAffordance/tools/serve_v2_annotation_app.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/v3_candidate_samples_v0_1.jsonl \
  --review-jsonl processed/metadata/v3_point_level_review_records.jsonl \
  --output-mask-root processed/vlm_candidate_v3/manual_refined_masks \
  --output-samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --port 8765 \
  --top-k-candidates 5 \
  --candidate-min-selected-votes 2
```

审查系统现在使用蓝白主色。左键用圆形 brush 增删点，右键旋转点云，滚轮缩放。

## 4. 打包已审查数据集

人工审查完成后，把 `checked/verified` 样本打包成第一版 reviewed dataset：

```bash
python MultiEEAffordance/tools/build_reviewed_dataset_release.py \
  --dataset-root MultiEEAffordance \
  --reviewed-samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --output-samples processed/metadata/reviewed_dataset_v0_1.jsonl \
  --summary-json processed/metadata/reviewed_dataset_summary_v0_1.json \
  --output-split-dir splits_reviewed_v0_1 \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --overwrite
```

输出的 `reviewed_dataset_v0_1.jsonl` 只包含人工点级审查通过的样本，不再把自动候选直接视为 GT。

## 5. 启动已审查数据集可视化系统

```bash
python MultiEEAffordance/tools/serve_reviewed_dataset_viewer.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/reviewed_dataset_v0_1.jsonl \
  --port 8780
```

如果还没有打包 release，也可以直接看人工审查输出：

```bash
python MultiEEAffordance/tools/serve_reviewed_dataset_viewer.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --port 8780
```

可视化系统是只读的，主要用于快速检查已经完成审查的数据集：按样本浏览、查看任务/执行器统计、旋转点云、突出显示目标执行器正样本点。

## 6. 2026-05-25 更新：v3 大规模队列二版

这版的核心变化是：队列不再只保留“已有可行执行器”的样本，而是按 `物体 + 任务 + 执行器` 展开。若物体和任务本身不匹配，例如剪刀执行 `open_pull`，直接用常识过滤掉；若物体任务匹配但某个执行器没有合适区域，例如洗碗机 `open_pull + suction/hook`，仍然保留一条空标签审查样本，让人工确认“该执行器无可用 affordance”。

推荐先从原始 3D-AffordanceNet zip 重新生成更大的弱标签样本池：

```bash
python MultiEEAffordance/tools/convert_3d_affordancenet.py \
  --dataset-root MultiEEAffordance \
  --zip raw/3d_affordancenet/full-shape.zip \
  --source-split val \
  --target-split val \
  --tasks pick_up,open_pull,press_push \
  --max-per-category 20 \
  --points-dir processed/points/3d_affordancenet_full_shape_val_batch_v3 \
  --candidate-dir processed/candidates/3d_affordancenet_full_shape_val_batch_v3 \
  --mask-dir processed/masks/3d_affordancenet_full_shape_val_batch_v3 \
  --manifest manifests/3d_affordancenet_full_shape_val_batch_v3_manifest.jsonl \
  --summary processed/metadata/3d_affordancenet_full_shape_val_batch_v3_summary.json \
  --overwrite
```

```bash
python MultiEEAffordance/tools/build_samples_jsonl.py \
  --dataset-root MultiEEAffordance \
  --manifest manifests/3d_affordancenet_full_shape_val_batch_v3_manifest.jsonl \
  --output processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --default-split val \
  --default-quality weak \
  --write-splits \
  --split-dir splits_v3_large_batch
```

生成大规模人工审查队列：

```bash
python MultiEEAffordance/tools/build_large_scale_review_queue.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --output-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --summary-json processed/metadata/v3_large_scale_review_queue_summary_v0_1.json \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --executor-scope all \
  --quality-scope all \
  --empty-policy review \
  --common-sense-filter \
  --limit 300 \
  --overwrite
```

`--limit 300` 用于第一批验证。确认流程稳定后可以去掉。当前旧版只有 47 条，是因为之前从小规模 `samples_checked_v0_1.jsonl` 出发，并且只保留 `feasible + needs_review`。新版会保留不可行执行器的空标签审查项，所以行数会明显增加。

运行 v3 pipeline：

```bash
CUDA_VISIBLE_DEVICES=1,2 python MultiEEAffordance/tools/run_v3_pipeline.py \
  --dataset-root MultiEEAffordance \
  --config configs/qwen3vl_sam2_pilot.yaml \
  --pilot-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --stages views,plan,ground,project,grow,render,coverage,build \
  --allow-empty \
  --overwrite
```

说明：

- `plan/ground/coverage` 都会显示进度条；这些阶段需要 VLM 对多视角逐条推理，速度慢是正常的。
- `run_v3_pipeline.py` 会自动把空标签审查行分出来，跳过 VLM 候选生成，并在 build 阶段写入 0 positive 的样本。
- `coverage` 会检查 VLM 目标部件是否被候选覆盖，便于定位“VLM 说有目标但候选没覆盖”的问题。
- `grow` 阶段会额外加入 source weak mask fallback，减少“候选太少，全部靠人工补”的情况。

启动人工审查：

```bash
python MultiEEAffordance/tools/serve_v2_annotation_app.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/v3_candidate_samples_v0_1.jsonl \
  --review-jsonl processed/metadata/v3_point_level_review_records.jsonl \
  --output-mask-root processed/vlm_candidate_v3/manual_refined_masks \
  --output-samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --port 8765 \
  --top-k-candidates 5 \
  --candidate-min-selected-votes 2
```

审查系统现在按物体分组，物体下面再切换不同任务和执行器；左侧按 pending/checked 分类。点到样本后，页面顶部会突出显示当前 `object / task / executor / review_mode`。灰色背景点也加深，方便判断候选区域和物体主体的关系。
