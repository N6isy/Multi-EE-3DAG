# 大规模人工审查与已审查数据集可视化

更新时间：2026-05-29

## 当前策略

当前分成两个阶段：

1. **旧任务候选生成阶段**仍使用 `pick_up`、`open_pull`、`press_push`，这是为了复用已经跑完的 val / train_100pcat 候选输出，避免覆盖旧数据。
2. **人工审查和 reviewed dataset 阶段**使用五任务：`lift`、`open`、`pull`、`press`、`push`。

旧任务到五任务的映射为：

| 旧任务 | 五任务 |
| --- | --- |
| `pick_up` | `lift` |
| `open_pull` | `open` + `pull` |
| `press_push` | `press` + `push` |
| `lift_carry` | `lift` |

旧任务候选只作为 proposal，不能直接作为五任务 GT。最终标签以网页人工审查后的 refined mask 为准。

旧候选生成阶段暂时只保留三类任务：

- `pick_up`
- `open_pull`
- `press_push`

`lift_carry` 与 `pick_up` 在当前点云数据和执行器定义下过于接近，因此在生成审查队列、运行 v3 pipeline、打包 reviewed dataset 时默认排除。原始数据不删除，后续如果重新区分任务定义，可以再恢复。

当前 v3 候选主线是：

```text
3D AffordanceNet samples
  -> channel-level review queue
  -> high_recall 3D part candidates
  -> VLM candidate ID selection
  -> executor/task rule filter
  -> human point-level review
  -> reviewed [N,4] dataset
```

注意：推荐主线不再使用旧的 `ground -> project -> grow` 候选生成方式。旧路径只保留为历史实验 fallback。

## 1. 生成大规模弱标签样本池

服务器原始数据位置：

- `/home/lzq/Multi-EE-3DAG/MultiEEAffordance/raw/3d_affordancenet/full-shape.zip`
- `/home/lzq/Multi-EE-3DAG/MultiEEAffordance/raw/partnet-mobility/partnet-mobility-v0.zip`

先从 3D-AffordanceNet full-shape validation split 生成较大的弱标签样本池：

```bash
python MultiEEAffordance/tools/convert_3d_affordancenet.py \
  --dataset-root MultiEEAffordance \
  --zip raw/3d_affordancenet/full-shape.zip \
  --source-split val \
  --target-split val \
  --tasks pick_up,open_pull,press_push \
  --max-per-category 20 \
  --points-dir processed/points/3d_affordancenet_full_shape_val_batch_v3 \
  --candidate-dir processed/candidates/3d_affordancenet_full_shape_val_batch_v3 \
  --mask-dir processed/masks/3d_affordancenet_full_shape_val_batch_v3 \
  --manifest manifests/3d_affordancenet_full_shape_val_batch_v3_manifest.jsonl \
  --summary processed/metadata/3d_affordancenet_full_shape_val_batch_v3_summary.json \
  --overwrite
```

再把 manifest 转成统一 samples JSONL：

```bash
python MultiEEAffordance/tools/build_samples_jsonl.py \
  --dataset-root MultiEEAffordance \
  --manifest manifests/3d_affordancenet_full_shape_val_batch_v3_manifest.jsonl \
  --output processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --default-split val \
  --default-quality weak \
  --write-splits \
  --split-dir splits_v3_large_batch
```

之前只看到 47 条，是因为旧队列来自小规模 `samples_checked_v0_1.jsonl`，并且只保留 `feasible + needs_review`。上面这套流程会从原始 zip 重新展开，样本规模会明显增加。

## 2. 生成 channel-level 审查队列

队列按 `object + task + executor` 展开。若物体和任务本身不匹配，例如剪刀执行 `open_pull`，会被常识过滤掉；若物体任务匹配但某个执行器没有合适区域，例如洗碗机 `open_pull + suction/hook`，仍保留为空标签审查样本，让人工确认“该执行器无可用 affordance”。

第一批建议先限制 300 条：

```bash
python MultiEEAffordance/tools/build_large_scale_review_queue.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --output-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --summary-json processed/metadata/v3_large_scale_review_queue_summary_v0_1.json \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --executor-scope all \
  --quality-scope all \
  --empty-policy review \
  --common-sense-filter \
  --limit-strategy round_robin_category_task_executor \
  --limit 300 \
  --overwrite
```

确认分布和流程稳定后，去掉 `--limit 300` 跑更大规模队列。

## 3. 先小批检查 high_recall 候选 overlay

这一步不跑 VLM，只看自研高召回候选是否足够覆盖目标部件，速度快，适合先观察效果。

```bash
python MultiEEAffordance/tools/run_v3_pipeline.py \
  --dataset-root MultiEEAffordance \
  --config configs/qwen3vl_sam2_pilot.yaml \
  --pilot-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --samples processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --candidate-source partseg \
  --part-proposal-backend high_recall \
  --stages views,part_propose,render \
  --limit 6 \
  --proposal-max-candidates 64 \
  --max-candidates 24 \
  --part-top-k 5 \
  --allow-empty \
  --overwrite
```

重点检查：

- 小部件是否被保留，例如 button、knob、switch、handle joint、thin leg。
- handle / loop / ring 这类结构是否有多个可选候选，而不是只剩一个 top-1。
- 候选是否允许部分重叠，但没有全部堆到同一大片主体区域。
- `need_review=true` 的不确定候选是否仍进入人工审查视野。

## 4. 跑完整 v3 候选生成 pipeline

完整流程会运行 VLM 语义规划、VLM 候选 ID 选择、规则过滤和 build 阶段，输出待人工审查的 `v3_candidate_samples_v0_1.jsonl`。

```bash
CUDA_VISIBLE_DEVICES=1,2 python MultiEEAffordance/tools/run_v3_pipeline.py \
  --dataset-root MultiEEAffordance \
  --config configs/qwen3vl_sam2_pilot.yaml \
  --pilot-csv processed/metadata/v3_large_scale_review_queue_v0_1.csv \
  --samples processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
  --candidate-source partseg \
  --part-proposal-backend high_recall \
  --stages views,plan,part_propose,render,part_select,part_filter,build \
  --proposal-max-candidates 64 \
  --max-candidates 12 \
  --part-top-k 5 \
  --allow-empty \
  --overwrite
```

参数说明：

- `--candidate-source partseg`：使用部件候选主线。
- `--part-proposal-backend high_recall`：使用自研高召回 3D 候选生成器。
- `--proposal-max-candidates 64`：候选生成阶段最多保留 64 个候选，保证 recall。
- `--max-candidates 12`：overlay / VLM 选择阶段展示前 12 个候选，控制 VLM 输入复杂度。
- `--part-top-k 5`：每个候选组保留 top-k，而不是只保留 top-1。
- `--allow-empty`：允许空标签审查样本进入 build，形成 0 positive 的待确认样本。

如果只想跑候选生成和 overlay，不要加 `plan/part_select/part_filter/build`；如果需要 VLM 帮忙选择候选，再使用完整命令。

## 5. 展开为五任务人工审查 samples

上一步输出的是旧任务候选 samples。正式人工审查前，需要展开为五任务：

```bash
python MultiEEAffordance/tools/expand_legacy_tasks_to_5tasks.py \
  --input MultiEEAffordance/processed/metadata/v3_candidate_samples_v0_1.jsonl \
  --output MultiEEAffordance/processed/metadata/v3_candidate_samples_v0_2_5tasks.jsonl \
  --summary-json MultiEEAffordance/processed/metadata/v3_candidate_samples_v0_2_5tasks_summary.json \
  --overwrite
```

这个输出是人工审查和 reviewer 分包的输入。旧任务候选路径会保留，新增 `source_task/source_sample_id/task_taxonomy_version/task_split_source/row_key` 追溯字段。

如果在数据存储盘 `/home/lzq/data` 上准备审查输入，把路径换成：

```bash
python MultiEEAffordance/tools/expand_legacy_tasks_to_5tasks.py \
  --input /home/lzq/data/MultiEEAffordance/processed/metadata/v3_candidate_samples_v0_1.jsonl \
```

## 7. 启动点级人工审查系统

建议 v3 审查时显式指定 v3 输出路径，避免继续写入 v2 默认文件：

```bash
python MultiEEAffordance/tools/serve_v2_annotation_app.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/v3_candidate_samples_v0_2_5tasks.jsonl \
  --review-jsonl processed/metadata/v3_point_level_review_records.jsonl \
  --output-mask-root processed/vlm_candidate_v3/manual_refined_masks \
  --output-samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --port 8765 \
  --top-k-candidates 8 \
  --candidate-min-selected-votes 2
```

审查系统现在按物体分组，物体下面再切换不同任务和执行器；左侧按 `pending/checked` 分类。点到样本后，页面顶部会突出显示当前 `object / task / executor / review_mode`。左键圆形 brush 增删点，右键旋转点云，滚轮缩放。

### 7.1 双人协作标注启动方式

正式双人协作标注时，不建议两位审查者共用上面的单一输出路径。应先把待审查样本按 `object_id` 分成两份，再分别启动两个端口：

```text
processed/annotation_batches/v0_2_5tasks/
  reviewer_a_samples.jsonl
  reviewer_b_samples.jsonl
  reviewer_a_review_records.jsonl
  reviewer_b_review_records.jsonl
  reviewer_a_refined_samples.jsonl
  reviewer_b_refined_samples.jsonl
  manual_refined_masks_reviewer_a/
  manual_refined_masks_reviewer_b/
```

`reviewer_a` 示例：

```bash
python MultiEEAffordance/tools/serve_v2_annotation_app.py \
  --dataset-root MultiEEAffordance \
  --samples processed/annotation_batches/v0_2_5tasks/reviewer_a_samples.jsonl \
  --review-jsonl processed/annotation_batches/v0_2_5tasks/reviewer_a_review_records.jsonl \
  --output-mask-root processed/annotation_batches/v0_2_5tasks/manual_refined_masks_reviewer_a \
  --output-samples processed/annotation_batches/v0_2_5tasks/reviewer_a_refined_samples.jsonl \
  --port 8765 \
  --top-k-candidates 8 \
  --candidate-min-selected-votes 2
```

`reviewer_b` 使用独立端口和独立输出：

```bash
python MultiEEAffordance/tools/serve_v2_annotation_app.py \
  --dataset-root MultiEEAffordance \
  --samples processed/annotation_batches/v0_2_5tasks/reviewer_b_samples.jsonl \
  --review-jsonl processed/annotation_batches/v0_2_5tasks/reviewer_b_review_records.jsonl \
  --output-mask-root processed/annotation_batches/v0_2_5tasks/manual_refined_masks_reviewer_b \
  --output-samples processed/annotation_batches/v0_2_5tasks/reviewer_b_refined_samples.jsonl \
  --port 8766 \
  --top-k-candidates 8 \
  --candidate-min-selected-votes 2
```

两位审查者都只处理自己样本文件中的条目。若需要一致性校准，可额外准备少量 overlap 样本，但 overlap 样本不应自动合并进正式 release，应先人工比较差异。

## 8. 打包已审查数据集

人工审查完成后，把 `checked/verified` 样本打包成第一版 reviewed dataset：

```bash
python MultiEEAffordance/tools/build_reviewed_dataset_release.py \
  --dataset-root MultiEEAffordance \
  --reviewed-samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --output-samples processed/metadata/reviewed_dataset_v0_1.jsonl \
  --summary-json processed/metadata/reviewed_dataset_summary_v0_1.json \
  --output-split-dir splits_reviewed_v0_1 \
  --include-tasks lift,open,pull,press,push \
  --overwrite
```

输出的 `reviewed_dataset_v0_1.jsonl` 只包含人工点级审查通过的样本，不把自动候选直接视为 GT。

双人协作标注时，先合并两份 refined samples：

```bash
cat \
  MultiEEAffordance/processed/annotation_batches/v0_2_5tasks/reviewer_a_refined_samples.jsonl \
  MultiEEAffordance/processed/annotation_batches/v0_2_5tasks/reviewer_b_refined_samples.jsonl \
  > MultiEEAffordance/processed/annotation_batches/v0_2_5tasks/merged_refined_samples.jsonl
```

再将 `--reviewed-samples` 指向：

```text
processed/annotation_batches/v0_2_5tasks/merged_refined_samples.jsonl
```

如果同一个 `row_key` 或 `sample_id + task + executor` 被两位审查者都保存过，合并前应列入 conflict review，不要自动覆盖。

如果还没有打包 release，也可以直接看人工审查输出：

```bash
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
```

可视化系统是只读的，主要用于快速抽检已经完成审查的数据集：按物体浏览、切换任务/执行器、查看统计、旋转点云、突出显示目标执行器正样本点。
