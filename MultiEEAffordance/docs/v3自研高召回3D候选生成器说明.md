# v3 自研高召回 3D Part Candidate Generator 说明

更新时间：2026-05-29

## 1. 当前决策

当前放弃把 PartSLIP++ 作为主候选生成器。v3 正式候选主线改为自研、无外部模型依赖的高召回 3D part candidate generator：

```text
原始点云 / 弱标签 / 多视角 index map / 几何特征
  -> high_recall 3D part candidates [K, N]
  -> VLM 只看候选 overlay 并选择候选 ID
  -> 执行器规则保守过滤
  -> 人工审查和点级精修
  -> [N,4] affordance mask
```

这个模块的第一目标是 recall，第二目标才是 precision。候选不是 ground truth，所有不确定区域都应进入人工审查，而不是在自动阶段过早删除。

当前协作标注策略：`high_recall` 作为 v0.1 稳定标注版本的候选来源，但不再在标注进行中频繁改动。当前可用版本冻结到 `annotation/mvp-v0.1`，后续候选生成器改进进入 `dev/high-recall-candidate-v0.2`。如果研发分支生成更好的候选，应另开 v0.2 批次重新跑候选和审查队列，不要覆盖 v0.1 的人工标注批次。

任务体系补充：本模块生成的是旧任务候选 proposal，主要任务名仍是 `pick_up/open_pull/press_push`，并兼容历史 `lift_carry`。人工标注主线已经切换为 `lift/open/pull/press/push`，需要先用 `expand_legacy_tasks_to_5tasks.py` 把旧候选 samples 展开，再交给 `serve_v2_annotation_app.py` 审查。旧候选不能直接作为五任务真值。

## 2. 设计原则

- 不过早删除低置信度候选：低置信度候选写入 `need_review=true`。
- 不只保留每类 part 的 top-1：默认每个候选组保留 `--part-top-k 5`。
- 允许同一个 3D 点属于多个候选：例如 handle 可以同时属于 `loop_handle_lip`、`small_part`、`visual_partial_component`。
- 尽量拆解整个物体：通过 coarse axis partition 把物体按 x/y/z 粗分，避免只出现少数边界点。
- 保留 small parts：按钮、旋钮、开关、handle joint、细腿等小部件有专门 small-part 组件。
- 保留 partially visible candidates：多视角前景组件和轴向 extreme 区域不会因为不完整而直接丢弃。
- 不确定候选只进入 review，不直接写入正例。

## 3. 已实现 backend

正式入口：

```bash
python MultiEEAffordance/tools/propose_v3_part_candidates.py \
  --dataset-root MultiEEAffordance \
  --pilot-csv processed/metadata/v3_test_review_queue_v0_1.csv \
  --samples processed/metadata/samples_v3_large_batch_v0_1.jsonl \
  --backend high_recall \
  --max-candidates 64 \
  --part-top-k 5 \
  --overwrite
```

当前 backend：

| backend | 当前角色 | 说明 |
| --- | --- | --- |
| `high_recall` | 默认主线 | 自研高召回候选生成器，无外部模型依赖 |
| `geometry` | 历史 fallback | 旧版几何候选生成器，用于复现实验 |
| `partslippp` | 可选 adapter | 已不作为主线，仅保留历史接口 |

## 4. 候选族设计

`high_recall` 会混合生成以下候选组：

| part_group | 作用 |
| --- | --- |
| `coarse_partition_*` | 按 x/y/z 轴粗分物体，保证主体、局部和普通面不会完全缺失 |
| `visual_partial_component` | 基于多视角 `point_index` 前景组件，保留部分可见结构 |
| `weak_mask_prior` | 保留已有弱标签和扩展后的弱标签区域 |
| `loop_handle_lip` | 宽松高曲率/线性组件，用于 handle、loop、ring、lip、hole boundary |
| `loop_handle_lip_strict` | 更严格的高曲率/线性 seed，便于人工精修边界 |
| `smooth_panel_surface` | 平滑/平面组件，用于 suction、press_push、panel、door surface |
| `small_part` | 小型高曲率/凸出组件，用于 button、knob、switch、joint、thin leg |
| `paired_parts` | 成对组件 union，用于 scissors finger holes、双把手、环状结构 |

每个候选元数据中会包含：

```json
{
  "candidate_id": "A",
  "candidate_name": "...",
  "candidate_family": "...",
  "part_group": "...",
  "need_review": true,
  "allows_overlap": true,
  "rank_in_group": 1,
  "retention_policy": "high_recall_top_k_per_group",
  "confidence_hint": "low|medium",
  "quality_hint": "...",
  "point_count": 123,
  "point_fraction": 0.06
}
```

## 5. 关键参数

| 参数 | 推荐值 | 说明 |
| --- | --- | --- |
| `--part-proposal-backend high_recall` | 默认 | 使用自研高召回候选 |
| `--proposal-max-candidates 64` | 64 | 生成阶段最多保留候选数 |
| `--max-candidates 12~24` | 小批建议 24，全量建议 12 | overlay/VLM 展示候选数 |
| `--part-top-k 5` | 5 | 每个 part group 保留 top-k |
| `--dedupe-iou 0.985` | 0.985 | 只去除几乎完全重复的候选 |
| `--small-part-max-fraction 0.10` | 0.10 | small part 最大占比 |
| `--min-points 4` | 4 | 保留小部件，不要设太高 |
| `--k-neighbors 24` | 24 | kNN 局部几何邻域 |

```bash
  --include-tasks pick_up,open_pull,press_push \
  --exclude-tasks lift_carry \
```

```bash
  --part-proposal-backend high_recall \
  --stages views,part_propose,render \
  --limit 6 \
  --proposal-max-candidates 64 \
  --max-candidates 24 \
  --part-top-k 5 \
  --allow-empty \
  --overwrite
```

检查：

```text
processed/vlm_candidate_v3/3d_candidates/<pilot_id>/candidate_manifest.json
processed/vlm_candidate_v3/3d_candidates/<pilot_id>/candidates.npz
processed/vlm_candidate_v3/candidate_overlays/<pilot_id>/
```

重点看：

- scissors 是否保留两个 finger holes / handle loops，而不是只给 blade；
- bag 是否保留 handle、handle joint、body partition；
- door/faucet 是否保留 handle/button/panel；
- button、knob、switch、thin leg 是否进入 `small_part` 或 `visual_partial_component`；
- 候选是不是太碎或太重叠。如果太多，先调 `--max-candidates`，不要急着降低 `--proposal-max-candidates`。

## 7. 人工审查流程

单人调试可以直接使用统一 v3 输出路径；正式双人协作标注请使用 `双人协作标注README.md` 中的 `reviewer_a/reviewer_b` 独立输出路径，避免两位审查者同时写入同一个 review log 或 mask 目录。

```bash
python MultiEEAffordance/tools/serve_v2_annotation_app.py \
  --dataset-root MultiEEAffordance \
  --samples processed/metadata/v3_candidate_samples_v0_1.jsonl \
  --review-jsonl processed/metadata/v3_point_level_review_records.jsonl \
  --output-mask-root processed/vlm_candidate_v3/manual_refined_masks \
  --output-samples processed/metadata/v3_manual_refined_samples_v0_1.jsonl \
  --port 8765 \
  --max-points 0 \
  --top-k-candidates 8
```

建议人工审查策略：

1. 先看候选列表中默认勾选区域。
2. 再打开候选预览，补选 `need_review=true` 但 VLM 没选中的可疑部件。
3. 最后用圆形 brush 做少量点级增加/删除。
4. 如果没有合适区域，保存为空 mask，不要强行标注。

## 9. 调参建议

| 问题 | 优先调整 |
| --- | --- |
| 候选太少，漏 handle/button | 提高 `--proposal-max-candidates`，提高 `--part-top-k` |
| 候选太碎 | 略增 `--min-points`，或降低 `--max-candidates` 只影响展示 |
| 小部件丢失 | 保持 `--min-points 4`，增大 `--small-part-max-fraction` |
| VLM 看不完候选 | 降低 `--max-candidates`，不要降低 `--proposal-max-candidates` |
| 候选重叠太多 | 降低 `--dedupe-iou` 到 `0.95`，但不要低于 `0.9` |
| 大主体太多 | 降低 `--max-candidate-fraction` 或依赖 rule filter/人工审查 |

## 10. 与旧方案的区别

- 不再依赖 Florence/box grounding 定位部件坐标。
- 不再依赖 PartSLIP++ 外部模型。
- 不把低置信候选提前删除，而是进入 `need_review=true`。
- 不把一个部件压成 top-1，而是按 part group 保留 top-k。
- 允许点重叠，以便 handle、ring、edge、small joint 同时被多个候选覆盖。
- 最终仍保持 `[N,4]`，只对应原始点云，不生成代理点。
