# 报错问题记录

本文档专门记录环境配置、依赖缺失、模型兼容性、路径迁移、服务器运行报错等问题。

记录原则：

- 这里记录“问题现象、原因判断、解决方式、当前状态”。
- `项目进度日志.md` 只记录数据构建、pipeline 设计、标注规范、实验阶段推进等实质性研究进展。
- 如果某个报错推动了 pipeline 设计改变，可以在项目进度日志中记录“设计决策”，但 traceback、依赖安装和兼容补丁细节仍放在本文档。

## 2026-05-17 Florence-2 `forced_bos_token_id` 兼容问题

### 触发命令

```bash
CUDA_VISIBLE_DEVICES=1,2 python MultiEEAffordance/tools/run_grounding_sam2.py \
  --dataset-root MultiEEAffordance \
  --config configs/qwen3vl_sam2_pilot.yaml \
  --pilot-id vlm_pilot_005 \
  --backend florence2 \
  --run-sam2 \
  --overwrite
```

### 问题现象

服务器端加载 Florence-2 本地权重时报错：

```text
'Florence2LanguageConfig' object has no attribute 'forced_bos_token_id'
```

完整 traceback 显示错误发生在：

```text
AutoConfig.from_pretrained(...)
configuration_florence2.py -> Florence2Config.__init__
configuration_florence2.py -> Florence2LanguageConfig.__init__
if self.forced_bos_token_id is None ...
```

关键点是：错误发生在 config 实例构造过程中，因此“模型加载后再 patch config 实例”太晚。

### 原因判断

- 该问题不是模型 API 配置错误，也不是权重路径错误。
- 更可能是 Florence-2 remote code 与服务器当前 `transformers` 版本之间的 config 字段兼容性问题。
- Florence-2 的 `Florence2LanguageConfig.__init__` 在字段初始化前访问了 `self.forced_bos_token_id`。
- 因为访问发生在 config 构造期间，需要先 patch Florence-2 config class，再实例化 config。

### 已采用修复

`tools/run_grounding_sam2.py` 中已加入兼容处理：

- 读取 `config.json` 中的 `auto_map["AutoConfig"]`。
- 使用 `transformers.dynamic_module_utils.get_class_from_dynamic_module` 先加载 Florence-2 config class，但不立即实例化。
- 对 `Florence2LanguageConfig` 等 config class 补齐中性默认属性：
  - `forced_bos_token_id = None`
  - `forced_eos_token_id = None`
  - `suppress_tokens = None`
  - `begin_suppress_tokens = None`
- 再调用 `config_class.from_pretrained(...)` 构造 config。
- 模型加载后和 `generate()` 前也会再次 patch config-like 对象，作为运行期兜底。
- 脚本异常退出时打印完整 traceback，方便后续定位。

### 当前状态

该问题已越过。服务器后续报错已经进入 Florence-2 modeling file 的依赖检查阶段。

## 2026-05-17 Florence-2 缺少 `einops` 和 `timm`

### 问题现象

服务器端继续运行 Florence-2 + SAM2 后，报错：

```text
[transformers] Encountered exception while importing einops: No module named 'einops'
[transformers] Encountered exception while importing timm: No module named 'timm'
ERROR: This modeling file requires the following packages that were not found in your environment: einops, timm. Run `pip install einops timm`
```

### 原因判断

- Florence-2 的 remote modeling code 依赖 `einops` 和 `timm`。
- 当前服务器虚拟环境尚未安装这两个包。
- 这是环境依赖缺失，不是数据、路径或标注逻辑问题。

### 解决方式

在服务器当前虚拟环境中执行：

```bash
python -m pip install einops timm
```

或者在更新代码后重新安装项目 VLM 依赖：

```bash
python -m pip install -r MultiEEAffordance/requirements-vlm.txt
```

### 已同步到项目

- `requirements-vlm.txt` 已加入：
  - `einops`
  - `timm`
- `docs/VLM语义部件引导标注Pipeline.md` 已加入 Florence-2 缺依赖说明。
- `docs/Qwen3-VL+SAM2远程运行说明.md` 已加入远程环境说明。

### 当前状态

等待服务器安装依赖后重跑 Florence-2 + SAM2 grounding，继续观察是否能够输出 `bag handle` 的 2D boxes。

## 2026-05-17 Florence-2 `_supports_sdpa` 兼容问题

### 问题现象

服务器端安装 `einops` 和 `timm` 后继续运行 Florence-2 + SAM2，报错：

```text
ERROR: 'Florence2ForConditionalGeneration' object has no attribute '_supports_sdpa'
```

完整 traceback 显示错误发生在：

```text
AutoModelForCausalLM.from_pretrained(...)
modeling_utils.py -> PreTrainedModel.__init__
_check_and_adjust_attn_implementation(...)
_sdpa_can_dispatch(...)
if not self._supports_sdpa:
```

### 原因判断

- 当前 `transformers` 版本会在模型初始化阶段检查 SDPA attention 支持情况。
- Florence-2 remote model class `Florence2ForConditionalGeneration` 没有定义 `_supports_sdpa`。
- 这属于 Florence-2 remote code 与当前 `transformers` attention dispatch 逻辑的兼容性问题。
- 该问题不是数据问题，也不是模型权重缺失问题。

### 已采用修复

`tools/run_grounding_sam2.py` 中加入两层处理：

- Florence-2 配置默认使用 `attn_implementation: eager`，避免初始化阶段走 SDPA capability check。
- 在加载 remote model class 后、实例化模型前，给 class 补齐：
  - `_supports_sdpa = False`
  - `_supports_flash_attn_2 = False`

`configs/qwen3vl_sam2_pilot.yaml` 中已加入：

```yaml
florence2:
  attn_implementation: eager
```

### 当前状态

等待服务器拉取代码后重跑。如果仍在模型初始化阶段报 attention 相关错误，下一步考虑固定 `transformers` 版本，或将 Florence-2 替换为 GroundingDINO 后端。

## 2026-05-17 Florence-2 `RobertaTokenizer.additional_special_tokens` 兼容问题

### 问题现象

服务器端模型权重加载完成后，初始化 Florence-2 processor 时报错：

```text
ERROR: RobertaTokenizer has no attribute additional_special_tokens
```

完整 traceback 显示错误发生在：

```text
AutoProcessor.from_pretrained(...)
processing_florence2.py -> Florence2Processor.__init__
tokenizer.additional_special_tokens
```

### 原因判断

- Florence-2 remote processor code 直接访问 `tokenizer.additional_special_tokens`。
- 当前服务器安装的 `transformers` / tokenizer 组合中，`RobertaTokenizer` 没有暴露这个直接属性。
- 相关信息仍存在于 tokenizer 的 `special_tokens_map` 或 `special_tokens_map_extended` 中。
- 这是 Florence-2 remote processor code 与当前 tokenizer API 的兼容性问题，不是数据或模型路径问题。

### 已采用修复

`tools/run_grounding_sam2.py` 中新增 `patch_tokenizer_additional_special_tokens()`：

- 在 `AutoProcessor.from_pretrained(...)` 之前执行。
- 给 `PreTrainedTokenizerBase` 补一个 `additional_special_tokens` property。
- getter 从 `special_tokens_map_extended` / `special_tokens_map` 中读取 `additional_special_tokens`。
- 该补丁不修改 tokenizer 词表，只是为 Florence-2 processor 提供兼容属性。

### 当前状态

等待服务器拉取代码后重跑。若 processor 初始化通过，下一步应进入逐视角 Florence-2 phrase grounding 和 SAM2 分割阶段。

## 2026-05-18 Florence-2 `attention_mask` 尺寸不匹配问题

### 问题现象

服务器端 Florence-2 processor 初始化通过后，进入逐视角 `generate()` 阶段时报错：

```text
ERROR: Attention mask should be of size (1, 1, 589, 589), but is torch.Size([1, 1, 12, 12])
```

完整 traceback 显示错误发生在：

```text
grounder.model.generate(...)
modeling_florence2.py -> self.language_model.generate(...)
encoder self attention
```

### 原因判断

- `processor(text=..., images=..., return_tensors="pt")` 返回的 `attention_mask` 只对应文本 token，长度约为 12。
- Florence-2 的 `generate()` 内部会把图像 token 和文本 token 组合后送入 language model，实际 encoder 序列长度变成 589。
- 将纯文本 `attention_mask` 直接传给 `model.generate()` 会导致 attention mask 尺寸不匹配。
- Florence-2 官方示例通常只传 `input_ids` 和 `pixel_values`，不传 `attention_mask`。

### 已采用修复

`tools/run_grounding_sam2.py` 中 Florence-2 `generate()` 调用已去掉：

```python
attention_mask=moved.get("attention_mask")
```

保留：

```python
input_ids=moved.get("input_ids")
pixel_values=moved.get("pixel_values")
```

### 当前状态

等待服务器拉取代码后重跑。若该问题越过，下一步应观察 Florence-2 是否能输出 `bag handle` 的有效 2D boxes，以及 SAM2 是否能生成非空 mask。

## 2026-05-18 Florence-2 `EncoderDecoderCache` 兼容问题

### 问题现象

服务器端去掉 `attention_mask` 后，Florence-2 进入 beam search generation 阶段，报错：

```text
ERROR: 'EncoderDecoderCache' object is not subscriptable
```

完整 traceback 显示错误发生在：

```text
modeling_florence2.py -> prepare_inputs_for_generation
past_length = past_key_values[0][0].shape[2]
```

### 原因判断

- 当前 `transformers` generation API 使用新版 `EncoderDecoderCache` 对象。
- Florence-2 remote code 中的 `prepare_inputs_for_generation` 仍按旧版 tuple/list cache 写法访问 `past_key_values[0][0]`。
- 这是 Florence-2 remote code 与当前 `transformers` cache API 的兼容性问题。
- 该问题不是数据、mask、SAM2 或渲染质量问题。

### 已采用修复

当前 pilot 阶段优先跑通闭环，因此采用兼容优先策略：

- 在 `configs/qwen3vl_sam2_pilot.yaml` 的 `florence2` 中加入：

```yaml
use_cache: false
```

- 在 `tools/run_grounding_sam2.py` 中：
  - 将 `use_cache` 应用到 Florence-2 config 和 nested config。
  - 加载模型后再次将 `use_cache` 应用到 model / config-like 对象。
  - `model.generate(...)` 显式传入 `use_cache=use_cache`。

### 当前状态

等待服务器拉取代码后重跑。该方式会牺牲一部分 generation 速度，但 pilot 只有少量视角，优先保证流程跑通。

如果后续继续出现 Florence-2 / `transformers` generation API 兼容问题，应考虑停止继续堆补丁，改为：

- 固定一套 Florence-2 已知兼容的 `transformers` 版本；
- 或切换到 GroundingDINO / Florence-2 独立环境作为 grounding 后端；
- 或先用 `manual-json` 外部 boxes 跑通 2D-to-3D 回投和融合闭环。

## 2026-05-18 Florence-2 跑通但输出 `boxes=0`

### 问题现象

服务器端 Florence-2 + SAM2 已经不再崩溃，能够输出 `grounding_summary.json`，但 8 个视角全部为：

```json
{
  "boxes": 0,
  "positive_pixels": 0,
  "mask_source": "sam2"
}
```

同时模型加载报告中出现：

```text
language_model.model.decoder.embed_tokens.weight | MISSING
language_model.model.encoder.embed_tokens.weight | MISSING
language_model.lm_head.weight                    | MISSING
```

服务器模型目录大小约为 3.0G，并同时包含：

```text
model.safetensors
pytorch_model.bin
```

### 原因判断

- `boxes=0` 表示 Florence-2 没有从 `bag handle` 等 query 中解析出有效 2D box。
- `positive_pixels=0` 是后续结果：SAM2 没有 box prompt，因此生成空 mask。
- 加载报告中的语言模型 embedding / lm_head missing 很可疑，可能说明当前优先加载的权重文件不完整或与 remote code 不匹配。
- 当目录同时存在 `model.safetensors` 和 `pytorch_model.bin` 时，`transformers` 通常会优先使用 safetensors；如果该文件缺语言模型关键参数，Florence-2 虽然能运行，但生成结果可能失效。

### 已采用修复和诊断增强

`configs/qwen3vl_sam2_pilot.yaml` 中加入：

```yaml
florence2:
  use_safetensors: false
```

目的：优先使用 `pytorch_model.bin`，验证是否可以消除 `language_model.* MISSING`。

`tools/run_grounding_sam2.py` 中增强输出：

- 每个视角的 `*_boxes.json` 现在保存 Florence-2 diagnostics。
- diagnostics 包含：
  - `query`
  - `prompt`
  - `generated_text`
  - `parsed`
  - `image_size`
- 即使 `boxes=[]`，也能检查 Florence-2 原始生成文本和 `post_process_generation` 解析结果。
